### Scenario 2: TELIS Shard Auto-Loading
```javascript
test('Agent receives correct shards on invocation', async () => {
  // 1. Invoke LLM Research Expert
  const agent = await invokeAgent('llm-research-expert');

  // 2. Verify 2 shards loaded
  expect(agent.context.shards).toHaveLength(2);

  // 3. Verify correct shards
  expect(agent.context.shards.map(s => s.name)).toEqual([
    'llm-shards.md',
    'midi-math.md'
  ]);

  // 4. Verify token budget
  const totalTokens = agent.context.shards.reduce((sum, s) => sum + s.tokens, 0);
  expect(totalTokens).toBeGreaterThan(1200);
  expect(totalTokens).toBeLessThan(1400);
});
```

## Key Design Decisions

**1. Real vs. Mock File System**:
- **Unit tests**: Mock fs when testing pure logic
- **Integration tests**: Use real file system to catch path issues
- **Rationale**: Integration tests must validate actual file operations

**2. Coverage Thresholds**:
- **90% for workflow-dispatcher**: Critical routing component, must be bulletproof
- **85% for other components**: Reasonable for supporting code
- **Rationale**: Balance thoroughness with development velocity

**3. Test Isolation**:
- Each test cleans up its state (delete .agent-state.json, unload shards)
- No test dependencies (can run in any order)
- **Rationale**: Prevent flaky tests, enable parallel execution

**4. Fixture Strategy**:
- Minimal fixtures in tests/fixtures/
- Generate test data programmatically when possible
- **Rationale**: Reduce maintenance burden, keep tests self-documenting
